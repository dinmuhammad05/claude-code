## Bu darsda nima o‘rganasiz

Oddiy tilda: tasavvur qiling, jamoangizga juda qobiliyatli yangi
dasturchi keldi. U tez o‘qiydi, ko‘p tilni biladi, terminalda erkin
ishlaydi. Lekin uning ikkita o‘ziga xosligi bor. Birinchisi — u loyihangiz
haqida **faqat o‘zi ochib o‘qigan narsani** biladi: kecha nima
kelishganingiz, qaysi fayl muhimligi, “tayyor” nimani anglatishi — bularni
u o‘zi topmaguncha yoki siz aytmaguncha bilmaydi. Ikkinchisi — u har
kuni ertalab **kechagi suhbatni eslamay** keladi. Faqat stolida qoldirilgan
yozuvlarni o‘qiydi.

**Claude Code** — xuddi shunday hamkasb. U kodni o‘qiydi, buyruqlarni
ishga tushiradi, fayllarni tahrirlaydi va natijaga qarab keyingi qadamni
tanlaydi. Bu “chatbot bilan gaplashish” emas: bu **ish bajaradigan agent**
bilan ishlash. Bu boshqa ko‘nikma. Ko‘pchilik dasturchilar uni chat kabi
ishlatadi va natijadan hafsalasi pir bo‘ladi. Sababi — model yomonligida
emas, ish **qanday tashkil qilinganida**.

Bu dars kursning poydevori. Qolgan o‘n to‘rtta dars — ruxsatlar,
kontekst, CLAUDE.md, subagentlar, hooks, MCP — hammasi shu darsdagi bitta
aqliy modelga tayanadi: **agent sikli, uning ish stoli (kontekst oynasi)
va “tayyor”ni isbotlaydigan tekshiruv**.

| Savol | Javob shu darsda | Bo‘lim |
| --- | --- | --- |
| Chat bilan agentning farqi nimada? | Harakat qilish qobiliyati | 1 |
| Claude Code vazifani qanday bajaradi? | Uch bosqichli sikl | 2–3 |
| Model nima qiladi, Claude Code nima qiladi? | Model va “harness” | 4 |
| Agent qaysi asboblar bilan ishlaydi? | Asboblar toifalari | 5 |
| Token nima va nega u muhim? | Token iqtisodi | 6 |
| Nega uzun sessiyada agent “aqlsizlanadi”? | Kontekst oynasi | 7–8 |
| Agent ishini qanday tekshirtirish kerak? | Tekshiriladigan maqsad | 9 |
| Xato yo‘ldan qanday qaytarish mumkin? | Esc, rewind, checkpoint | 10–11 |
| Ertaga u bugungi ishni eslaydimi? | Sessiyalar va xotira | 12 |

<Callout type="maslahat" title="Qanday o'qish kerak">
Har yangi tushuncha avval **oddiy tilda**, keyin **mexanizm** sifatida,
oxirida **amaliy qoida** bilan beriladi. `Chuqurroq` bloklarini birinchi
o‘qishda tashlab ketsangiz ham bo‘ladi. Bo‘lim oxiridagi **nazorat
savollariga** avval o‘zingiz javob bering. Darsdagi faktlar Claude Code’ning
rasmiy hujjatlariga tayanadi (20-bo‘lim). Claude Code tez o‘zgaradi:
interfeys yozuvlari va menyular siz ko‘rgandan biroz farq qilishi mumkin,
lekin sikl, kontekst va tekshiruv g‘oyalari o‘zgarmaydi.
</Callout>

<Callout type="info" title="Kimlar uchun">
Kurs kamida bir yil dasturlash tajribasi bor, git va terminal bilan
ishlay oladigan dasturchilar uchun. Claude Code’ni hali o‘rnatmagan
bo‘lsangiz, bu darsni baribir o‘qing — o‘rnatish 2-darsda. Amaliyot
qismida (17-bo‘lim) esa Claude Code kerak bo‘ladi.
</Callout>

## 1. Chat va agent: farqi bitta so‘zda — harakat

Oddiy tilda: chat-yordamchi — telefon orqali maslahat beradigan usta.
Siz muammoni tasvirlaysiz, u “mana bu murvatni burab ko‘ring” deydi. Burash,
natijani ko‘rish va qayta qo‘ng‘iroq qilish — sizning ishingiz. Agent esa
uyingizga kelgan usta: o‘zi qaraydi, o‘zi buraydi, o‘zi suv ochib tekshiradi.

Chat oynasida AI bilan ishlash odatda shunday kechadi:

1. Siz xato matnini va kodning bir qismini nusxalab joylaysiz.
2. Model javob yozadi: “mana bu qatorni o‘zgartiring”.
3. Siz kodni editorga ko‘chirasiz, testni ishga tushirasiz.
4. Xato boshqa joyda chiqadi. Yana nusxalaysiz. Model esa sizning
   loyihangizning qolgan qismini **hech qachon ko‘rmagan**.

Bu jarayonda **sikl sizning qo‘lingizda**: kontekstni siz yig‘asiz,
harakatni siz qilasiz, natijani siz tekshirasiz. Model faqat “o‘ylash”
qismini bajaradi.

Agentda sikl **modelning o‘zida**. Rasmiy hujjat buni bitta jumlada
aytadi: asboblarsiz Claude faqat matn bilan javob bera oladi, asboblar
bilan esa **harakat qila oladi**. Claude Code’ga “testlar yiqilyapti,
tuzat” desangiz, u o‘zi testni ishga tushiradi, xato chiqqan faylni o‘zi
ochadi, tuzatadi va testni **yana** ishga tushiradi.

Bu farqning **ikki tomoni** bor va kurs ikkalasi haqida.

**Kuch.** Agent o‘nlab qadamni sizsiz bajaradi. Yaxshi qo‘yilgan vazifada
siz bir necha daqiqa qaraysiz, keyin boshqa ish bilan shug‘ullanasiz.

**Xavf.** Agent **haqiqiy** buyruqlarni **haqiqiy** kompyuterda bajaradi.
Fayl o‘chirishi, paket o‘rnatishi, `git push` qilishi mumkin. Chatdagi
noto‘g‘ri javob — shunchaki noto‘g‘ri matn. Agentning noto‘g‘ri harakati
esa diskda, git tarixida yoki serverda iz qoldiradi. Shuning uchun Claude
Code’da **ruxsatlar tizimi** bor (2–3-bo‘limlar va 3-dars).

<Check q="Chat-yordamchida 'sikl sizning qo'lingizda' degani nima?">

buyruq ishga tushirish) va natijani tekshirish — uchalasini ham siz
qilasiz. Model faqat matn yozadi. Agentda bu uch qadamni model asboblar
orqali o‘zi bajaradi, siz esa yo‘naltirasiz va natijani qabul qilasiz.
</Check>

## 2. Agent sikli: uch bosqich

Oddiy tilda: tajribali usta ham shunday ishlaydi — avval **qaraydi**
(nima buzilgan?), keyin **qiladi** (murvatni almashtiradi), keyin
**tekshiradi** (suv oqyaptimi?). Oqsa — yana qaraydi. Bu aylana muammo
yo‘qolguncha davom etadi.

Rasmiy hujjat Claude Code ishini aynan uch bosqichga bo‘ladi:

1. **Kontekst yig‘ish** — fayllarni o‘qish, kod bo‘ylab qidirish, loyiha
   tuzilishini tushunish, kerak bo‘lsa buyruq bilan holatni bilish
   (`git status`, test natijasi).
2. **Harakat qilish** — faylni tahrirlash, yangi fayl yaratish, buyruq
   ishga tushirish.
3. **Natijani tekshirish** — testlar, build, linter, skrinshot: o‘zgarish
   haqiqatan maqsadga olib keldimi?

<Flow nodes={["Vazifa", "Kontekst yig'ish", "Harakat", "Tekshirish", "Maqsadga yetdimi?", "Yo'q — yana kontekst", "Ha — natija"]} caption="Agent sikli. Hujjat ta'kidlaydi: bosqichlar bir-biriga aralashib ketadi va bir vazifada ko'p marta aylanadi." />

Hujjatdagi muhim kuzatuv: **bosqichlar bir-biriga aralashadi**. Kod
bazasi haqidagi savolga javob berish uchun faqat birinchi bosqich yetarli
bo‘lishi mumkin. Xatoni tuzatish esa uchala bosqichdan **qayta-qayta**
o‘tadi: o‘qidi → tuzatdi → test yiqildi → yana o‘qidi → yana tuzatdi.

### 2.1 Har aylanish — bitta “o‘ylash + asbob” juftligi

Ichkarida sikl juda oddiy. Model har safar bitta narsani hal qiladi:
**hozir qaysi asbobni qanday argument bilan chaqiraman** yoki **ish
tugadi, javob yozaman**. Claude Code asbobni bajaradi, natijani
(fayl matni, buyruq chiqishi, xato) modelga qaytaradi. Model shu yangi
ma’lumot bilan yana qaror qiladi.

<Flow nodes={["Model: 'Read kassa.py'", "Claude Code faylni o'qiydi", "Fayl matni kontekstga qo'shiladi", "Model: 'Bash python -m unittest'", "Test chiqishi kontekstga qo'shiladi", "Model: 'Edit kassa.py ...'"]} caption="Har qadamda natija kontekstga qo'shiladi. Keyingi qaror shu to'plangan kontekst asosida." />

Shu sxemadan uchta muhim xulosa chiqadi. Kursning qolgan qismi
asosan shu uchtasining oqibati:

1. **Model faqat kontekstdagi narsani biladi.** U o‘qimagan faylni
   bilmaydi. U ishga tushirmagan testning natijasini bilmaydi. U sizning
   boshingizdagi talabni — siz yozmaguningizcha — bilmaydi.
2. **Har qadam kontekstni to‘ldiradi.** Har o‘qilgan fayl, har buyruq
   chiqishi oynada joy egallaydi. Joy cheklangan (7-bo‘lim).
3. **Sikl tekshiruv signali bilan to‘xtaydi.** Agar “tayyor”ni
   tekshiradigan narsa bo‘lmasa, model “menimcha tayyor” degan taxmin
   bilan to‘xtaydi (9-bo‘lim).

### 2.2 Siz sikl ichidasiz

Sikl avtomatik aylanadi, lekin siz uning **ichidasiz**. Hujjat aytadi:
istalgan payt to‘xtatib, Claude’ni boshqa yo‘nalishga burishingiz,
qo‘shimcha kontekst berishingiz yoki boshqa yondashuvni so‘rashingiz
mumkin. Buning amaliy tafsilotlari 10-bo‘limda: `Esc`, navbatga yozish
va rewind.

<Check q="Nega xatoni tuzatish vazifasi uch bosqichdan bir necha marta o'tadi, savolga javob esa ko'pincha bitta bosqichda tugaydi?">
Savolga javob — faqat bilim: fayllarni o‘qish va tushuntirish yetarli,
hech narsa o‘zgarmaydi, tekshiradigan natija yo‘q. Xatoni tuzatishda esa
har harakatdan keyin natijani ko‘rish kerak: test hali ham yiqilsa,
yangi ma’lumot (yangi xato matni) paydo bo‘ladi va u yangi kontekst
yig‘ishga, keyin yangi harakatga olib keladi.
</Check>

## 4. Model va harness: kim nima qiladi

Oddiy tilda: Claude Code ikki qismdan iborat. Birinchisi — **miya**: til
modeli, u o‘ylaydi va qaror qiladi. Ikkinchisi — **tana**: qo‘llar
(asboblar), ko‘zlar (fayl o‘qish, buyruq chiqishi) va xotira daftari
(kontekst). Miya kuchli, lekin tanasiz u hech narsa qila olmaydi. Tana esa
miyasiz qaror qabul qilmaydi.

Rasmiy hujjat buni shunday ta’riflaydi: agent sikli ikki komponentga
tayanadi — **o‘ylaydigan modellar** va **harakat qiladigan asboblar**.
Claude Code — model atrofidagi qatlam: u asboblarni beradi va model
ko‘radigan kontekstni boshqaradi. Bu atrofdagi qatlam **agentic harness**
deb ataladi. “Harness” so‘zma-so‘z “jabduq” — otning kuchini aravaga
uzatadigan anjom.

| Qism | Nima qiladi | Misol |
| --- | --- | --- |
| Model (Claude) | Vazifani tushunadi, kodni o‘qib mulohaza qiladi, keyingi qadamni tanlaydi, kod yozadi | “Avval testni ishga tushiraman, keyin xato chiqqan funksiyani o‘qiyman” |
| Asboblar | Modelning qarorini haqiqiy harakatga aylantiradi | `Read`, `Edit`, `Bash`, `WebFetch` |
| Kontekst boshqaruvi | Model nimani ko‘rishini belgilaydi; oyna to‘lganda eski chiqishlarni tozalaydi, kerak bo‘lsa suhbatni qisqartiradi | Avtomatik compact, `/context` |
| Ruxsatlar | Qaysi harakat so‘rovsiz, qaysi biri so‘rov bilan, qaysi biri umuman taqiqlangan | Manual rejim, allow/deny qoidalari |
| Bajarilish muhiti | Kod qayerda ishlaydi: sizning kompyuteringizda yoki bulutda | Lokal terminal, claude.ai/code |

Bu ajratish amalda **juda muhim**, chunki ikki xil narsa ikki xil
yo‘l bilan boshqariladi:

- **Model xulqi** — so‘z bilan boshqariladi: vazifa matni, CLAUDE.md,
  misollar. Bu **tavsiya**: model odatda amal qiladi, lekin kafolat yo‘q.
- **Harness xulqi** — sozlama bilan boshqariladi: ruxsat qoidalari,
  rejimlar, sandbox, hooks. Bu **majburiy**: model nima “xohlashidan”
  qat’i nazar ishlaydi.

Hujjatdagi qoida buni aniq aytadi: ruxsat qoidalarini **Claude Code
ijro etadi, model emas**. Prompt yoki CLAUDE.md dagi ko‘rsatmalar Claude
nima qilishga **urinishini** shakllantiradi, lekin Claude Code nimaga
**ruxsat berishini** o‘zgartirmaydi.

<Callout type="xato" title="Eng ko'p uchraydigan xato">
“CLAUDE.md ga ‘hech qachon .env faylini o‘qima’ deb yozdim — endi xavfsiz”.
Yo‘q. Bu — modelga iltimos. Ko‘pincha bajariladi, lekin bu **xavfsizlik
chegarasi emas**. Haqiqiy taqiq — ruxsat qoidasi (masalan, `.env` uchun
`Read` ni deny qilish) yoki hook. Bu 3, 5 va 12-darslarda batafsil.
</Callout>

<Check q="Jamoa 'testlarni hech qachon o'chirma' degan qoidani kafolatlamoqchi. Uni qayerga yozish kerak — CLAUDE.md gami yoki boshqa joyga?">
CLAUDE.md ga yozish foydali — model odatda amal qiladi. Lekin
**kafolat** kerak bo‘lsa, bu harness darajasida bo‘lishi kerak: masalan,
test fayllarini tahrirlashga deny qoidasi yoki o‘zgarishni bloklaydigan
hook. So‘z — tavsiya, sozlama — majburiyat.
</Check>

## 5. Asboblar: agentning qo‘llari

Oddiy tilda: ustaning asboblar qutisi bor — o‘lchov lentasi, otvertka,
dril. Usta qanchalik mohir bo‘lmasin, qutida bo‘lmagan asbob bilan
ishlay olmaydi. Claude Code’ning asboblar qutisi ham aniq ro‘yxat.

Hujjat o‘rnatilgan asboblarni beshta toifaga ajratadi: fayl amallari,
qidiruv, bajarish, veb va kod tahlili (oxirgisi qo‘shimcha plagin talab
qiladi). Alohida — orkestratsiya: subagent ishga tushirish, sizga savol
berish, vazifalar ro‘yxati.

| Toifa | Asboblar | Nima qiladi | Ruxsat so‘raydimi |
| --- | --- | --- | --- |
| Fayl o‘qish | `Read` | Fayl matnini o‘qiydi | Yo‘q (ish papkasidan tashqari — ha) |
| Fayl yozish | `Edit`, `Write` | Aniq joyni almashtiradi / yangi fayl yozadi | Ha |
| Qidiruv | `Glob`, `Grep` yoki Bash’dagi `find`, `grep` | Fayl nomi va matn bo‘yicha qidiradi | Yo‘q |
| Bajarish | `Bash` (Windows’da `PowerShell` ham) | Shell buyrug‘ini ishga tushiradi | Ha (faqat o‘qish uchun buyruqlar — yo‘q) |
| Veb | `WebFetch`, `WebSearch` | Sahifa yuklaydi, qidiradi | Ha |
| Orkestratsiya | `Agent`, `AskUserQuestion`, `TaskCreate`… | Subagent, savol, vazifalar ro‘yxati | Yo‘q |

“Ruxsat so‘raydimi” ustuni — Manual (standart) rejim uchun. Boshqa
rejimlarda bu o‘zgaradi (3-dars).

### 5.1 Ikki nozik tafsilot

**Edit — “aniq satrni almashtirish”.** `Edit` faylni qaytadan yozmaydi:
u faylda aniq bir matn bo‘lagini topib, boshqasiga almashtiradi. Shuning
uchun avval faylni o‘qishi shart. Bu yaxshi xususiyat: o‘zgarish kichik,
diff aniq, tasodifan faylning boshqa qismi buzilmaydi.

`Glob` va `Grep` standart to‘plamda bor. Sessiya jurnalida
`Bash(grep -rn ...)` ko‘rsangiz — bu xato emas, shunday bo‘lishi kerak.

ma’lumoti, MCP asboblari nomlari, skill tavsiflari, shaxsiy va loyiha
CLAUDE.md lari. Hujjatdagi illyustratsiyada bular jami ~7 850 token.
</QA>

<QA q="Yaxshi tekshiruvning to'rt xususiyatini sanang.">
Agent o‘zi ishga tushira oladi; natija bir ma’noli; u haqiqatan siz
xohlagan narsani o‘lchaydi; agent uni “aldab” (testni o‘zgartirib) o‘ta
olmaydi yoki buni diff’da ko‘rasiz.
</QA>

<QA q="Esc va Esc Esc ning farqi nima?">
`Esc` joriy javob yoki asbob chaqiruvini to‘xtatadi, shu paytgacha
qilingan ish saqlanadi, Claude keyingi ko‘rsatmani kutadi. Bo‘sh
kiritishda `Esc` `Esc` rewind menyusini ochadi: kod va/yoki suhbatni
oldingi nuqtaga qaytarish mumkin. Kiritishda matn bo‘lsa, `Esc` `Esc`
avval qoralamani tozalaydi.
</QA>

<QA q="Qaysi o'zgarishlarni rewind qaytara olmaydi?">
Bash orqali qilingan fayl o‘zgarishlari, boshqa dastur yoki sessiya
o‘zgartirgan fayllar va tashqi tizimlarga ta’sir: ma’lumotlar bazasiga
yozish, API chaqiruvlari, xabarlar, deploy, `git push`. Ular ruxsat
rejimi va qoidalari bilan boshqariladi; git esa eng ishonchli zaxira.
</QA>

<QA q="Agent bir xil xatoda uchinchi marta adashdi. Nima qilasiz?">
“Correcting over and over” naqshi. Kontekst noto‘g‘ri urinishlar bilan
to‘lgan. `/clear` (yoki yangi sessiya) va o‘rganganlaringizni hisobga
olgan aniqroq vazifa: belgilar, nima ishlamagani, qayerdan qidirish,
“tayyor” sharti.
</QA>

<QA q="Nega Linux'da sessiya jurnalida Grep asbobi ko'rinmasligi mumkin?">
Hujjatga ko‘ra macOS, Linux va WSL da `Glob` va `Grep` asboblari
standart to‘plamda yo‘q; qidiruv Bash orqali `find` va `grep` bilan
bajariladi. Windows’da ular standart to‘plamda bor.
</QA>

<QA q="'Ertaga davom etamiz' — agent ertaga bugungi ishni qanday 'eslaydi'?">
O‘zi eslamaydi: sessiyalar mustaqil. Variantlar: `claude --continue` /
`--resume` bilan aynan shu sessiyani davom ettirish, yoki (yaxshirog‘i
uzoq ish uchun) bugungi xulosani faylga yozdirish — reja, CLAUDE.md
yangilanishi, commit xabari — va ertaga toza sessiyada shu fayldan
boshlash.
</QA>

<QA q="Bir vazifa uchun 'tayyor' shartini yozing: 'API'ga sahifalash qo'sh'.">
Masalan: “Tayyor degani — `GET /orders?page=2&limit=20` uchun yangi
testlar yozilgan va `npm test` to‘liq o‘tadi; mavjud testlar
o‘zgartirilmagan; oxirida test chiqishi va `git diff --stat` ni
ko‘rsat.” Asosiysi: buyruq, kutilgan natija va dalil.
</QA>
