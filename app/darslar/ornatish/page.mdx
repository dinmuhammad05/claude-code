## 2. O‘rnatish: bitta buyruq

Oddiy tilda: Claude Code’ni o‘rnatishning bir nechta yo‘li bor, lekin
hujjat bittasini **tavsiya qiladi** — “native” o‘rnatuvchi. U o‘zi
yangilanib turadi va qo‘shimcha dastur talab qilmaydi.

### 2.1 Tavsiya etilgan usul (native)

macOS, Linux yoki WSL:

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

Windows PowerShell:

```powershell
irm https://claude.ai/install.ps1 | iex
```

Windows CMD:

```bat
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
```

O‘rnatgandan keyin **yangi terminal** oching — shunda `claude` buyrug‘i
PATH’da paydo bo‘ladi.

### 2.2 Boshqa usullar

| Usul | Buyruq | Avto-yangilanish |
| --- | --- | --- |
| Native (tavsiya) | yuqoridagi skript | Ha, fonda |
| Homebrew | `brew install --cask claude-code` | Yo‘q |
| WinGet | `winget install Anthropic.ClaudeCode` | Yo‘q |
| npm | `npm install -g @anthropic-ai/claude-code` | Qo‘lda |
| apt, dnf, apk | rasmiy repozitoriylar | Yo‘q |

npm uchun **Node.js 22** yoki undan yangisi kerak. Hujjatdagi qat’iy
ogohlantirish: **`sudo npm install -g` ishlatmang**. Ruxsat xatosi
chiqsa — sudo bilan emas, npm sozlamasini tuzatish bilan hal qilinadi
(12-bo‘lim).

<Check q="Homebrew bilan o'rnatdingiz, bir oydan keyin hamkasbingizda yangi buyruq bor, sizda yo'q. Nega?">

## 3. Tekshirish va yangilash

O‘rnatgandan keyin uchta buyruq bilan holatni tekshiring:

| Buyruq | Nima qiladi |
| --- | --- |
| `claude --version` | Versiyani chiqaradi, masalan `2.1.211 (Claude Code)` |
| `claude doctor` | Sessiya ochmasdan o‘rnatish va sozlamalar diagnostikasi (faqat o‘qiydi) |
| `claude update` | Yangilanishni hozir tekshiradi va o‘rnatadi |

### 3.1 Yangilanish kanallari

Native o‘rnatish ikki kanaldan birini kuzatadi:

- **`latest`** — standart: yangi versiya chiqishi bilan;
- **`stable`** — hujjatga ko‘ra odatda taxminan **bir hafta eski**,
  ya’ni muammolari allaqachon ko‘rilgan versiya.

Ishlab chiqarishga yaqin jamoada `stable` xotirjamroq. Tanlash:
sessiyada `/config` → avto-yangilanish kanali, yoki sozlamada
`"autoUpdatesChannel": "stable"`.

<Callout type="maslahat" title="Sessiya ichidagi tekshiruv">
Sessiya ichida ham ikki foydali buyruq bor: **`/status`** — versiya, model,
akkaunt va ulanish holati; **`/doctor`** — sozlashni tekshiradi va
tuzatishlarni taklif qiladi (siz tasdiqlaganingizdan keyin qo‘llanadi).
</Callout>

## 4. Kirish va API kalit tuzog‘i

Oddiy tilda: Claude Code’ga birinchi marta kirganingizda brauzer ochiladi,
siz akkauntingiz bilan tasdiqlaysiz — tamom. Lekin bitta yashirin tuzoq
bor, u ko‘pchilikni pul yo‘qotishga olib keladi.

### 4.1 Kirish

1. Terminalda `claude` ni ishga tushiring.
2. Brauzer ochiladi; ochilmasa — `c` tugmasi bilan havolani nusxalab,
   o‘zingiz oching.
3. Akkauntingizni tanlab tasdiqlang.

Keyin: **`/login`** — akkauntni almashtirish, **`/logout`** — chiqish,
**`/status`** — hozir qaysi akkaunt bilan ishlayotganingiz.

WSL, SSH yoki konteynerda brauzer boshqa kompyuterda ochiladi. Bunda
brauzer bergan kodni terminaldagi “Paste code here if prompted” joyiga
qo‘yasiz.

### 4.2 Tuzoq: ANTHROPIC_API_KEY

Hujjatdagi ogohlantirish (mazmunan): **obunangiz bo‘lsa-yu, muhitda
`ANTHROPIC_API_KEY` o‘rnatilgan bo‘lsa, siz tasdiqlaganingizdan keyin
Claude Code obunani emas, shu kalitni ishlatadi.**

Bu nimaga olib keladi:

- sarf obuna limitidan emas, **API hisobidan** (token uchun to‘lov) ketadi;
- kalit eskirgan yoki o‘chirilgan tashkilotga tegishli bo‘lsa —
  tushunarsiz autentifikatsiya xatolari.

Kalit ko‘pincha boshqa loyiha uchun `.bashrc`, `.zshrc` yoki `.env`
orqali o‘rnatilgan bo‘ladi va unutiladi.

```bash
echo $ANTHROPIC_API_KEY      # bo'sh bo'lishi kerak (obuna bilan ishlasangiz)
unset ANTHROPIC_API_KEY      # joriy terminal uchun olib tashlash
```

Keyin sessiyada `/status` bilan qaysi hisob ishlatilayotganini tekshiring.
Doimiy yechim — kalitni shell sozlama faylidan olib tashlash.

<Deep title="Kirish ustuvorligi: Claude Code qaysi hisobni tanlaydi">
Hujjatda hisob ma’lumotlari tartibi bor. Yuqoridagisi pastdagidan ustun:

1. Bulut provayderi (`CLAUDE_CODE_USE_BEDROCK` va boshqalar o‘rnatilgan bo‘lsa)
2. `ANTHROPIC_AUTH_TOKEN`
3. `ANTHROPIC_API_KEY`
4. `apiKeyHelper` skripti
5. `CLAUDE_CODE_OAUTH_TOKEN` (`claude setup-token` bilan, CI uchun)
6. Profil yoki federatsiya
7. `/login` orqali obuna — Pro, Max, Team va Enterprise uchun standart

Ko‘rinib turibdiki, obuna eng pastda. Yuqoridagi istalgan narsa
o‘rnatilgan bo‘lsa, u ustun keladi. Bulut sessiyalari (claude.ai/code)
esa hujjatga ko‘ra har doim obuna hisobidan foydalanadi.
</Deep>

<Check q="Do'stingizda Max obunasi bor, lekin oy oxirida API hisobidan katta to'lov keldi. Birinchi nimani tekshirasiz?">
Muhitda `ANTHROPIC_API_KEY` o‘rnatilganmi: `echo $ANTHROPIC_API_KEY` va

## 5. Qaysi muhit: terminal, IDE yoki ilova

Oddiy tilda: Claude Code bitta, lekin uni bir necha “eshik”dan ochish
mumkin. Ichidagi agent bir xil — farq qayerda o‘tirib ishlashingizda.

| Muhit | Nima uchun yaxshi | Bilish kerak |
| --- | --- | --- |
| **Terminal (CLI)** | To‘liq imkoniyatlar, skriptlar, serverlar | Skript va Agent SDK faqat CLI’da |
| **VS Code** kengaytmasi | Editor ichida ishlash, diff’larni ko‘rish | VS Code 1.94+; kengaytma `claude` ni PATH ga **qo‘shmaydi** |
| **JetBrains** plagini | IntelliJ, PyCharm, WebStorm… ichida | Plagin CLI’ni IDE terminalida ishga tushiradi — **CLI’ni alohida o‘rnatish shart** |
| **Desktop** ilova | Vizual review, parallel sessiyalar | Linux’da beta |
| **Web** (claude.ai/code) | Bulutda ishlaydi, kompyuter yopilsa ham davom etadi | GitHub kerak; ba’zi buyruqlar yo‘q |
| **Mobil** ilova | Bulut sessiyalarini boshlash va kuzatish | Kodni telefonda yozish uchun emas |

### 5.1 Qaysi birini tanlash

Kurs **terminalni asosiy** deb oladi, chunki:

- hamma imkoniyat birinchi bo‘lib shu yerda;
- keyingi darslardagi `claude -p`, hooks, CI — terminal buyruqlari;
- IDE’lar ham ichkarida baribir CLI’dan foydalanadi (JetBrains holatida
  to‘g‘ridan-to‘g‘ri).

Lekin bu majburiyat emas. Amaliy maslahat: **terminalda o‘rganing,
keyin qulay muhitga o‘ting.** Kod o‘qishni editorda afzal ko‘rsangiz — VS
Code kengaytmasi. Uzoq vazifani kompyuterdan uzoqda davom ettirmoqchi
bo‘lsangiz — web.

### 5.2 Bulut sessiyalarining farqi

Web’dagi sessiya sizning kompyuteringizda emas, Anthropic’ning bulutdagi
virtual mashinasida ishlaydi. Hujjatga ko‘ra u yerda:

- `/clear` yo‘q — yangi sessiyani yon paneldan boshlaysiz;
- `/plugin`, `/resume` kabi faqat-terminal buyruqlar yo‘q;
- kompyuteringizdagi plaginlar yuklanmaydi;
- muhitdagi API kalitlar ishlatilmaydi — har doim obuna.

<Check q="VS Code kengaytmasini o'rnatdingiz, lekin terminalda 'claude: command not found'. Nima bo'ldi?">
Hujjatga ko‘ra VS Code kengaytmasi `claude` buyrug‘ini shell PATH’ga
qo‘shmaydi. Terminalda ishlatish uchun CLI’ni alohida o‘rnatish kerak
(2-bo‘lim). JetBrains’da esa aksincha — plagin CLI’siz umuman ishlamaydi.
</Check>

## 6. Windows: native yoki WSL

Oddiy tilda: Windows’da Claude Code ikki xil yashashi mumkin — to‘g‘ridan-
to‘g‘ri Windows’da (native) yoki Windows ichidagi Linux’da (WSL).

| | Native Windows | WSL 2 | WSL 1 |
| --- | --- | --- | --- |
| O‘rnatish | PowerShell yoki CMD skripti | Linux skripti (WSL ichida) | Linux skripti |
| Bash asbobi | Git for Windows bo‘lsa | Ha | Ha |
| Sandbox | **Yo‘q** | Ha | Yo‘q |

Native Windows’da Git for Windows ixtiyoriy, lekin hujjatga ko‘ra Bash va
Monitor asboblari uchun kerak. Bo‘lmasa, Claude buyruqlarni PowerShell
orqali bajaradi. Git Bash topilmasa, sozlamaning `env` qismida
`CLAUDE_CODE_GIT_BASH_PATH` ko‘rsatiladi.

**Tavsiya:** loyihangiz Linux serverda ishlasa yoki sandbox kerak bo‘lsa
(3-dars) — **WSL 2**. Sof Windows loyihasi (.NET, PowerShell skriptlar)
bo‘lsa — native.

## 7. Terminalni sozlash

Oddiy tilda: Claude Code terminal ichida ishlaydi, shuning uchun bir-ikki

### 7.1 Ko‘p qatorli so‘rov

- **Hamma joyda ishlaydi:** `Ctrl+J`, yoki qator oxirida `\` va `Enter`.

  Warp, Apple Terminal, Windows Terminal.
- VS Code, Cursor, Zed va eski Alacritty’da `Shift+Enter` uchun bir marta
  **`/terminal-setup`** ni ishga tushiring.
- Juda uzun vazifa uchun 1-darsdagi `Ctrl+G` — so‘rovni matn muharririda
  yozish.

### 7.2 Boshqa qulayliklar

| Nima | Qanday |

## 9. /init va birinchi CLAUDE.md

Oddiy tilda: CLAUDE.md — har sessiya boshida agentning stoliga
qo‘yiladigan “loyiha qo‘llanmasi” (1-dars, 7-bo‘lim). `/init` uning
birinchi qoralamasini yozib beradi.

Hujjatga ko‘ra `/init`:

- kod bazasini tahlil qiladi va **build buyruqlari, test ko‘rsatmalari
  va loyiha konventsiyalari** bilan CLAUDE.md yozadi;
- CLAUDE.md allaqachon bo‘lsa — **ustidan yozmaydi**, yaxshilashlarni
  taklif qiladi;
- `CLAUDE_CODE_NEW_INIT=1` bilan interaktiv rejim: CLAUDE.md, skills va
  hooks’dan qaysilarini sozlashni so‘raydi va fayl yozishdan oldin taklifni
  ko‘rsatadi.

### 9.1 /init dan keyin nima qilish kerak

`/init` — qoralama, tayyor hujjat emas. Uni **o‘qing va qisqartiring**:

1. **Noto‘g‘ri** narsalarni o‘chiring — agent loyihani noto‘g‘ri tushungan
   bo‘lishi mumkin.
2. **O‘z-o‘zidan ko‘rinadigan** narsalarni o‘chiring (“bu Python loyihasi”).
   Har qator har sessiyada token yeydi.
3. **Agent bilmaydigan** narsani qo‘shing: “pullar tiyinda, butun son”,
   “`main` ga to‘g‘ridan-to‘g‘ri push qilinmaydi”.
4. Test va build buyruqlari **aniq** yozilganini tekshiring.
5. Commit qiling — CLAUDE.md jamoa bilan bo‘lishiladi.

CLAUDE.md’ni qanday yozish — butun 5-darsning mavzusi. Hozircha bitta
qoida: **qisqa va aniq** — amaliyotda 80 qatordan oshmasligi kerak.

<Check q="Loyihada CLAUDE.md allaqachon bor. /init ni ishga tushirsangiz, u o'chib ketadimi?">
Yo‘q. Hujjatga ko‘ra CLAUDE.md mavjud bo‘lsa, `/init` uning ustidan
yozmaydi — yaxshilash takliflarini beradi. Baribir har qanday o‘zgarishni
git diff orqali ko‘rib chiqing.
</Check>
